# Gachi Streak 🔥

Спільний трекер щоденного стрику для двох людей, які вчать Go, з жорсткою системою покарань за прокрастинацію.

Концепція, тон і гардероб ачівок описані в [біблії проєкту](docs/BIBLE.md).

- **Сервер** (Go + SQLite) рахує стрики, дедлайни й наказання.
- **Клієнт для Windows** живе в треї, показує обидва стрики й міняє шпалери робочого столу, коли ти халтуриш.

> v1 — лише Windows-клієнт. Сервер збирається під будь-яку ОС.

## Як це працює

| Стан | Коли | Що робить клієнт |
|---|---|---|
| ✅ `safe` | сьогодні вже є активність | повертає твої шпалери |
| ⏳ `pending` | активності ще нема, до дедлайну > 5 год | нічого |
| ⚠️ `warning` | активності нема, до дедлайну ≤ 5 год | шпалери з `images\warning`, звук попередження, зміна картинки кожні 30 хв |
| 💀 `failed` | дедлайн пропущено | стрик → 0, шпалери з `images\failed`, звук провалу |

- Дедлайн — **місцева північ** у часовому поясі користувача (кожен має свій).
- Активність зараховується трьома способами (можна комбінувати):
  1. кнопкою в треї (`POST /ping`);
  2. **локальним комітом** — клієнт сам перевіряє вказані папки з git-репозиторіями; пушити не обов'язково;
  3. **push на GitHub** — сервер дивиться публічні події (можна обмежити одним репозиторієм).
- Вийти з програми, щоб зняти покарання, не вийде: шпалери лишаються. Знімає їх тільки зарахована активність. Для демонстрації екрана є «Пауза 15 хв».

## Швидкий старт

### 1. Сервер

Linux / macOS:

```bash
go mod tidy            # перший раз: підтягне залежності й створить go.sum
go build -o bin/gachi-server ./cmd/server

# додати учасників (токен показується один раз)
./bin/gachi-server user add -name alex  -tz Europe/Lisbon -github AlexSol -repo AlexSol/go-diary
./bin/gachi-server user add -name buddy -tz Europe/Kyiv   -github buddy-login

./bin/gachi-server serve -addr :8080
```

Windows (PowerShell) — обов'язково з `.exe`, інакше Windows не знає, чим запускати файл, і питає «Select an app to open»:

```powershell
go mod tidy
go build -o bin\gachi-server.exe .\cmd\server

.\bin\gachi-server.exe user add -name alex -tz Europe/Lisbon -github AlexSol
.\bin\gachi-server.exe serve -addr :8080
```

Деплой на Fly.io (~$2–3/міс) — покроково в [docs/deploy-fly.md](docs/deploy-fly.md).

Або в Docker:

```bash
docker build -t gachi-server .
docker run -d -p 8080:8080 -v gachi-data:/data --name gachi gachi-server
docker exec gachi /gachi-server user add -name alex -tz Europe/Lisbon
```

Параметри `serve`: `-db gachi.db`, `-warn 5h`, `-tick 1m`, `-github-interval 10m` (0 — вимкнути), `-debug`.
Змінні середовища: `GACHI_DB`, `GACHI_ADDR`, `GITHUB_TOKEN` (необов'язково, піднімає ліміт GitHub API).

Інші команди: `user list`, `user token -name alex` (перевипустити токен), `user github -name alex -github LOGIN -repo owner/repo`.

### 2. Клієнт (Windows)

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
# або з Linux/macOS: make client-win
```

Локальна збірка має версію `dev` і не перевіряє оновлень. Git-хеш Go вшиває в бінарник сам, якщо збирати з репозиторію. Версію, хеш і посилання на сайт показує пункт трею «ℹ️ Про програму».

1. Запусти `bin\gachi-client.exe` — він створить `%APPDATA%\GachiStreak\config.json`, відкриє вікно налаштувань і залишиться в треї (демо вже працює).
2. Впиши адресу сервера й токен і натисни «Зберегти» — зміни застосовуються одразу, перезапуск не потрібен. Пізніше вікно відкривається з трею («⚙️ Налаштування») або кнопкою ⚙ на віджеті. `config.json` можна правити й вручну («📝 Відкрити config.json»): клієнт підхопить зміни сам за кілька секунд.

   Якщо конфіг зламаний або порожній токен, програма не закривається: проблема видна першим рядком меню трею.
3. Картинки й звуки вже вшиті в `.exe`: 5 шпалер для попередження і 7 звуків ([assets/](assets/README.md)). При першому запуску вони розпакуються в `%APPDATA%\GachiStreak\images\…` та `…\sounds\…`. Свої `.jpg/.png/.bmp` і `.wav/.mp3` просто додай у ці папки, щоразу береться випадковий файл. У папку, де вже є твої файли, стандартні не підкладаються.
4. У меню трею увімкни «Запускати з Windows».

#### Локальні репозиторії

Додай у `config.json` шляхи до репозиторіїв, у яких вчиш Go:

```json
"local_repos": ["C:\\code\\go-diary", "C:\\code\\gachi-streak"],
"local_author_emails": []
```

Під час кожного опитування, поки день ще не зараховано, клієнт виконує `git log --all` у кожній папці. Якщо там є коміт, автор якого — ти, з датою автора «сьогодні» у твоєму часовому поясі, день зараховується автоматично (джерело `local_git`).

- Хто такий «ти»: за замовчуванням це `git config user.email` кожного репо, тож підтягнуті коміти напарника не рахуються. Можна явно перелічити адреси в `local_author_emails`.
- Потрібен `git` у `PATH`. Консоль при цьому не блимає.
- Після змін у конфігу перезапусти клієнт. Стан перевірки видно в меню трею (рядок «📁 …»).

У вікні налаштувань є все основне: сервер і токен, віджет (режим, тема, персонаж, фони для кожного стану з превʼю), шпалери й звуки покарань, локальні репозиторії й відстеження активності, сповіщення. Ключі, яких там нема, вікно не чіпає.

Приклад конфігу — [`examples/client-config.json`](examples/client-config.json). Звук — папка з `.wav/.mp3` (грає випадковий), шлях до одного `.wav/.mp3` або системний аліас (`SystemHand`, `SystemExclamation`).

> Якщо конфіг створено старою версією, там стоїть `"warning_sound": "SystemExclamation"` і `"failed_sound": "SystemHand"`. Щоб увімкнути вшиті звуки, заміни на `"%APPDATA%"`-шляхи до папок, наприклад `"C:\\Users\\you\\AppData\\Roaming\\GachiStreak\\sounds\\warning"` і `"...\\sounds\\failed"`.

### Віджет

Маленьке вікно 320×300 з обома стриками, живими таймерами до дедлайну, станом ✅⏳⚠️💀, рядком «🟢 у GoLand · 47хв», кнопкою «✅ Я сьогодні вчив Go» та часом у програмах за сьогодні. Кнопка 🎨 перемикає тему, ⚙ відкриває налаштування, 🌐 — веб-дашборд, ✕ ховає віджет.

Біля кнопки «✅» живе **персонаж** — чібі з пов'язкою кольору теми. Він реагує на твій стан: `safe` — спокійний, грає м'язами й махає; `pending` — дрімає й позіхає; `warning` — нервує, пітніє й клацає батогом; `failed` — злиться й тупотить. Коли день зараховано, він святкує. Клік по ньому — випадкова дія. Вимикається в налаштуваннях або `"widget_character": false`.

**Атаки на екран.** Час від часу персонаж кидає **сніжки** або **розливає молоко** по всьому монітору: шматки вилітають з його рук, розбиваються, стікають і за кілька секунд зникають. Кліки проходять крізь них, фокус вони не забирають. Коли стан стає ⚠️, летять сніжки, при 💀 — молоко; між цим атаки бувають приблизно раз на `screen_attack_minutes` хвилин (0 = лише при зміні стану). Їх не буває в повноекранних іграх і відео, під час презентацій, на паузі «🙈 15 хв» і коли ти понад 5 хв не за компом. Спробувати: «🧪 Демо» → «❄️ Сніжки / 🥛 Молоко по екрану» або кнопки в налаштуваннях.

```json
"screen_attacks": true,
"screen_attack_minutes": 45
```

Ефект живе в окремому пакеті [`internal/splash`](internal/splash): сцена й малювання не залежать від ОС (є тести і `SPLASH_PREVIEW=<папка> go test ./internal/splash -run Preview` для PNG-превʼю), а на Windows кожен шматок — окреме прозоре layered-вікно. Перетягується за шапку, позиція запам'ятовується. Біля країв екрана (ближче за 20 px) віджет **прилипає** до краю робочої області свого монітора, тобто не заїжджає під таскбар.

Режими (меню трею → «🪟 Віджет» → «Режим» або `widget_mode` у `config.json`):

- `"desktop"` (за замовчуванням) — гаджет на робочому столі, завжди **під** вікнами;
- `"overlay"` — **поверх** усіх вікон, як оверлей Discord.

```json
"show_widget": true,
"widget_mode": "desktop",
"widget_snap_px": 20,
"widget_theme": "gachi"
```

`widget_snap_px: 0` вимикає прилипання.

Теми (меню трею → «🪟 Віджет» → «Тема», кнопка 🎨 на віджеті або `widget_theme`): `gachi` (за замовчуванням, помаранчева), `dark`, `light`, `neon`, `matrix`. Невідома назва = `gachi`.

#### Фон віджета: картинка, анімація або відео

Формати: `.jpg`, `.png`, `.webp` (статичний або анімований) і `.webm` (відео грає без звуку, по колу). Замість файлу можна вказати папку: тоді береться випадковий файл із неї.

Фон може бути один на всі стани або свій для кожного стану: `safe`, `pending`, `warning`, `failed`. Якщо для стану нічого не вказано, береться `default`.

Найпростіше обрати фон у «⚙️ Налаштування» → «🎬 Фон віджета»: для кожного стану там є превʼю всіх файлів (відео грає при наведенні), «🎲 Випадковий» із папки стану, «🚫 Без фону» і «➕ Свій файл…».

З коробки клієнт розпаковує вшиті кліпи в `%APPDATA%\GachiStreak\widget\<стан>` і бере фон звідти. Свої файли можна просто покласти в ці папки: вшиті розпаковуються лише в порожні папки, тож власні файли не перезаписуються. Якщо в конфігу вказати `widget_background` самому, це замінить стандартні папки повністю, а стан без значення залишиться зі звичайним фоном теми (або з `default`). Щоб вимкнути фон, вкажіть `"widget_background": ""`. Коли стан змінюється (зокрема в демо), фон міняється, а для папки обирається новий випадковий файл.

```json
"widget_background": {
  "default": "C:\\Users\\you\\Pictures\\widget\\calm.webp",
  "warning": "C:\\Users\\you\\Pictures\\widget\\warning",
  "failed":  "C:\\Users\\you\\Pictures\\widget\\failed.webm"
},
"widget_background_dim": 0.55
```

Для одного фону на все вистачить рядка: `"widget_background": "C:\\...\\bg.webm"`. `widget_background_dim` задає, наскільки колір теми перекриває фон, щоб текст лишався читабельним: від `0` (фон як є) до `1` (фону не видно).

Рекомендовано: до ~5 МБ, 5–15 с, ширина близько 640 px. Конвертація з GIF/MP4:

```bash
ffmpeg -i in.gif -vf "scale=640:-1,fps=24" -c:v libwebp -loop 0 -q:v 70 bg.webp
ffmpeg -i in.mp4 -vf "scale=640:-1" -c:v libvpx-vp9 -crf 36 -b:v 0 -an bg.webm
```

Віджет показує те, що клієнт уже отримав від сервера, тому окремого входу не потрібно. Потрібен Microsoft Edge WebView2 Runtime, у Windows 10/11 він зазвичай уже встановлений. Win+D («показати робочий стіл») ховає й віджет, як і будь-яке вікно.

### Сповіщення про ачівки

Раз на хвилину клієнт питає сервер про прогрес. Щойно відкривається нова ачівка, з'являється сповіщення Windows («🏆 Ачівку відкрито! Перша горутина · +40 XP»). Клік по ньому відкриває сторінку ачівок у браузері. У меню трею є рядок «🏆 Ачівки: N / 21», він теж веде на цю сторінку.

Кожну ачівку показують один раз: де її побачили першою (веб чи клієнт), там вона й вважається показаною. Сповіщення йде від імені Windows PowerShell, бо в портативного `.exe` немає власного ідентифікатора застосунку для тостів. Вимкнути можна так:

```json
"achievement_notifications": false
```

### Мережа (для адмінів)

Пункт трею «📡 Мережа: N запитів · M помилок» показує все, що клієнт надіслав на сервер від запуску:

- час від запуску, кількість запитів і помилок (мережеві збої та HTTP-статуси від 400, з відсотком);
- трафік: скільки відправлено і отримано. Рахуються реальні байти по мережі, разом із TLS і заголовками;
- кількість TCP-з'єднань, середній і максимальний час відповіді, остання помилка;
- розбивка за ендпоінтами (`GET /status`, `POST /presence` …): запити, помилки, середній час.

Лічильники оновлюються кожні 5 секунд і живуть, доки працює клієнт. Перечитування конфігу їх не скидає. «📋 Скопіювати звіт» кладе повний звіт у буфер обміну, щоб одразу вставити в чат. «📝 Записати звіт у client.log» додає той самий звіт у лог і відкриває його.

### Статистика програм (як у Discord)

Клієнт кожні 5 секунд дивиться, яка програма на передньому плані, і рахує час у ній. Зберігається **лише назва програми** (`GoLand`, `Chrome`, `Windows Terminal`), заголовки вікон не читаються ніколи. Якщо 5 хвилин немає руху миші чи натискань клавіш, це вважається AFK і в статистику не йде.

- Напарник бачить «🟢 Зараз у GoLand · 47хв» або «💤 AFK» у веб-дашборді та в меню трею.
- У веб-дашборді є топ програм за сьогодні і статистика за 7 днів. У треї є підменю «📊 Сьогодні в програмах».
- Це статистика для аудиту: день вона **не зараховує**.

Налаштування в `config.json`:

```json
"activity_tracking": true,
"share_activity": true,
"activity_ignore": ["Telegram.exe", "KeePassXC.exe"]
```

`share_activity: false` залишає статистику тільки локально, у треї. Програми з `activity_ignore` не рахуються взагалі.

### Демо-режим

У меню трею є «🧪 Демо». Він потрібен, щоб перевірити покарання, не чекаючи дедлайну:

- **⚠️ Показати попередження** / **💀 Показати провал** — ставить шпалери цього режиму і грає його звук. Повторний клік показує наступну картинку.
- **🔊 Звук попередження / провалу** — тільки звук.
- **⏹ Вимкнути демо** — повертає твої шпалери, далі знову діє реальний стан із сервера.

Поки демо активне, опитування сервера шпалери не чіпає. Після перезапуску клієнта демо скидається.

### Релізи й оновлення

1. `git tag v0.3.0 && git push origin v0.3.0`.
2. GitHub Actions ([release.yml](.github/workflows/release.yml)) проганяє тести, збирає `gachi-client.exe` з версією з тегу й публікує GitHub Release з `checksums.txt`.
3. Сервер раз на 15 хв читає останній реліз (`-release-repo`, за замовчуванням `AlexSol/Gachi-Streak`) і віддає його на `GET /client/version`.
4. Клієнт раз на годину питає сервер. Якщо є новіша версія: пункт «⬆️ Доступна нова версія» у треї, кнопка `⬆ v0.3.0` у віджеті й одне Windows-сповіщення на версію. Клік відкриває сторінку релізу. Перевірити одразу можна з меню трею: «ℹ️ Про програму» → «🔍 Перевірити оновлення».

Якщо змінився API і старі клієнти зламаються, задай мінімальну версію: `fly secrets set GACHI_CLIENT_MIN=0.3.0` (або `-client-min`). Старші клієнти покажуть «⛔ Онови клієнт» червоним, а сповіщення повторюватиметься при кожному запуску.

Зібрати реліз локально для перевірки: `make client-win VERSION=0.3.0`.

## Веб-інтерфейс

`https://<сервер>/app/` — вхід за інвайт-токеном і дашборд обох стриків з кнопкою «вчив Go». Деталі й локальна розробка — [docs/frontend.md](docs/frontend.md).

## API

`GET /` — сторінка «в розробці» для браузера (українська або англійська, за мовою браузера/системи).
Невідомі адреси: у браузері — тематична сторінка 404 (теж двомовна), для API-клієнтів — JSON `{"error":"not found"}`.


Усі запити, окрім `/healthz` і `/client/version`, з заголовком `Authorization: Bearer <token>`.

```bash
curl -X POST -H "Authorization: Bearer $T" -d '{"note":"channels"}' http://localhost:8080/ping
curl -H "Authorization: Bearer $T" http://localhost:8080/status
```

`GET /status` повертає обох учасників: стрик, рекорд, стан, дедлайн, секунди до нього, останній провал.

`GET /client/version` повертає останній реліз клієнта: `latest`, `min`, `url`, `download`, `sha256`.

## Структура

```
cmd/server        — HTTP API + воркери + CLI для користувачів
cmd/client        — трей-агент для Windows
frontend          — веб-інтерфейс (Vite + Preact + TypeScript)
internal/webui    — вшитий у сервер зібраний фронт (/app/)
internal/streak   — чиста доменна логіка (дні, дедлайни, стани)
internal/store    — SQLite (modernc, без CGO; тег cgosqlite → mattn/go-sqlite3)
```
