# Ранги й ачівки

Усе рахується на сервері з історії (`activities` і `events`) при кожному `GET /progress`. Нічого не зберігається окремо, тож правила можна міняти без міграцій. Логіка — у `internal/progress` (чисті функції, покриті тестами).

## XP

| Що | XP |
|---|---|
| Зарахований день | +30 |
| Відкрита ачівка | +XP ачівки |
| Пропущений дедлайн | −50 |

XP не опускається нижче нуля. Ранг = сумарний XP, тому після провалів ранг можна втратити.

## Драбина рангів

| Рівень | Ранг | XP | Go |
|---|---|---|---|
| 1 | Slave | 0 | `fmt.Println("Hello, World")` |
| 2 | Jabroni | 100 | `if err != nil { panic(err) }` |
| 3 | Boy Next Door | 300 | `go func() { … }()` |
| 4 | Performance Artist | 700 | `select { case v := <-ch: }` |
| 5 | Boss of This Gym | 1 500 | `context.WithTimeout(…)` |
| 6 | Deep Dark Gopher | 3 000 | `runtime.GOMAXPROCS(0)` |
| 7 | Dungeon Master | 6 000 | `go tool pprof` |

Нагороди рангів (freeze-слоти, паки звуків тощо) поки лише описані на сторінці — механіки ще немає.

## Ачівки

Детектор `auto` — працює вже зараз, з історії активностей:

- **Стрік:** 7 / 30 / 100 / 365 днів поспіль.
- **Удвох:** 7 днів поспіль, коли зараховано обом; 30 спільних днів.
- **Ганьба:** перший пропущений дедлайн; активність о 23:50–23:59; знову 7 днів поспіль після провалу.
- **Секретна:** активність о 02:00–04:59 (за часовим поясом користувача).

Детектор `code` — ачівки за код. Для них у користувача має бути GitHub-логін (`user github -name … -github LOGIN`). GitHub-чекер раз на `-github-interval` бере публічні події `PushEvent`, для кожного нового push отримує diff (`compare before...head`, для нової гілки чи force push — `commits/{head}`) і повний вміст змінених `.go` файлів. Пакет `internal/codescan` розбирає їх через `go/ast`, але конструкція зараховується лише тоді, коли рядок, з якого вона починається, був доданий. Тому старий код нічого не відкриває.

| id | Правило |
|---|---|
| `goroutine` | `go` statement |
| `channel` | `make(chan T)` |
| `select` | `select` з 2+ `case` |
| `context` | `context.WithCancel` / `WithTimeout` / `WithDeadline` (і `…Cause`) |
| `generics` | функція з type parameters |
| `errwrap` | `fmt.Errorf("…%w…")`, сумарно 5 разів |
| `first_test` / `benchmark` / `fuzz` | `func TestXxx(t *testing.T)` / `BenchmarkXxx(b *testing.B)` / `FuzzXxx(f *testing.F)` у `*_test.go` |
| `table_test` | `[]struct{…}` і `t.Run(name, func…)` в одному тесті |
| `nil_map` (секретна) | `var m map[K]V` без `make`, потім `m[k] = v` |

Кожен push аналізується один раз (таблиці `code_scans` і `code_findings`). За один прохід на користувача аналізується не більше 5 push і 30 `.go` файлів на push. Решта чекає наступного проходу. Стрічка подій кешується за ETag, а відповідь 304 не витрачає ліміт GitHub. Без `GITHUB_TOKEN` діє ліміт 60 запитів на годину і видно лише публічні репозиторії.

## Збереження і сповіщення

Відкриті ачівки зберігаються в `achievements_unlocked`. Доступ до таблиці йде через репозиторій `store.AchievementRepo`, а сервер працює з ним через інтерфейс `server.AchievementRepository`. Воркер дедлайнів щохвилини (а також кожен `GET /progress`) перераховує ачівки і записує нові. Збережена ачівка лишається відкритою, навіть якщо правило згодом зміниться. Дата відкриття — день, коли умову виконано вперше.

`GET /progress` позначає власні ще не показані ачівки прапорцем `new`. Веб показує тост «Ачівку відкрито» і викликає `POST /achievements/seen`.

## Розпаковка

Кожна ачівка має свою модель трусів (`frontend/src/briefs.tsx`). Щойно ачівка відкрилась, у вебі вона спершу лежить запакованою пачкою з віконцем і бейджем «Розпакуй!». Перший клік програє ефект відкриття зі звуком (Web Audio, без файлів):

- **Розпаковка:** пачка рветься, модель вистрибує, промені й конфеті;
- **Кольоровий спін:** чорний силует крутиться, колір заливає знизу вгору, спалах;
- **Gachi-флекс:** падіння з ударом, трясіння екрана, пил, ♂ і напис за рідкістю (до 50 XP «BOY NEXT DOOR», до 300 «BOSS OF THIS GYM», далі «DUNGEON MASTER»);
- **Ганьба:** глітч із розщепленням RGB, сумний тромбон, штамп «ГАНЬБА».

Для звичайних ачівок ефект випадковий з перших трьох, для категорії «ганьба» завжди останній. Ефект можна пропустити кліком. Розпаковка зберігається на сервері (`achievements_unlocked.opened_at`, `POST /achievements/{id}/open`). Десктоп-клієнт лише сповіщає і нічого не розпаковує.

На період MVP на кожній відкритій картці є кнопки «▶ …», щоб переглянути будь-який ефект (`DEBUG_EFFECTS` у `frontend/src/Progress.tsx`).

## Локальне тестування

```bash
make unlock-all NAME=alex   # відкрити всі ачівки (без NAME — усім; DB=шлях, за замовчуванням gachi.db)
make lock-all NAME=alex     # стерти збережені; ті, умови яких виконані, повернуться на наступному проході
```

Команди `gachi-server dev …` є лише в збірці з `-tags dev` і працюють напряму з файлом бази. HTTP-ендпоінта для них немає, і в релізний бінарник (Dockerfile, `make server*`) вони не потрапляють.

Тексти ачівок — у `frontend/src/i18n.ts` (ключ = `id`).
